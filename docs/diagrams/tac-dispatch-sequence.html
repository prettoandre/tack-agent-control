Sequence · tack-agent-control

One run, from tac dispatch to a pull request

The run's state (chips on control's lifeline) changes only when control reads verifiable facts from the runner: herdr's agent state, the plan's checkboxes, the branch head and an existing PR. The agent's own report is never trusted.

  1. tac dispatch <project> <plan> [--host auto] [--agent claude|codex]; host from projects.yaml.
  2. The runner runs git fetch and checks the plan is on origin/<base>; otherwise 422 plan_not_found and no run is created. Then the run is queued until its host is ok and has a free slot (maxRuns, default 2).
  3. Run moves to preparing. The runner adds worktree ~/worktrees/<project>/<run> on run/<run>-<slug> (later a tack branch spec/NNN-slug-wN), opens a herdr tab and saves a state file, then answers 201.
  4. herdr agent start runs in the background (up to 60 s); it never sends the prompt. Later the pane runs tack wave run <spec> --wave N --run-id <id> instead.
  5. Each poll reports facts; decide() in control maps them to a state.
  6. On the first idle poll the runner types the prompt, then checks the pane: still in the input box gets enter, absent is re-sent, in the transcript counts as delivered (at most 3 attempts, 4 s apart). Progress: plan checkboxes today, tack wave status --json (tack.status/v1) later.
  7. agentStatus, promptSent, progress, prUrl, headSha.
  8. The first run in an untrusted folder shows Claude Code's trust dialog; permission prompts do the same. The owner answers from the phone's key bar (down, enter) over the terminal WebSocket.
  9. control records every input in run_events with time and login, then forwards it.
  10. herdr agent send-keys; a text prompt while blocked returns agent_blocked.
  11. The agent pushes the run branch and opens a PR (under tack, the driver does this after the gate).
  12. Inside a later status poll: gh pr list --head <branch> --state all. Idle plus a PR is succeeded; idle without a PR for 15 minutes is needs_attention.
